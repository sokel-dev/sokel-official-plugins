# YouTube

取 YouTube 视频的信息、下载视频/音频、抓字幕文本。底层是 [yt-dlp](https://github.com/yt-dlp/yt-dlp)。

## 能做什么

- **取视频信息** —— 标题、频道、时长、播放量、简介、可选清晰度、有哪些字幕。不下载，秒回。
  下载前先用它判断「这个视频值不值得下」。
- **下载视频** —— 交回一个平台文件，画布里往下游传的是文件引用（不是几百 MB 的字节）。
  选清晰度，或直接填「取视频信息」列出的某个 `format_id`。
- **下载音频** —— 只取音频轨，**默认不转码**（上游的音频本来就是独立一条流，原样拿最快也无损失）。
  要 MP3 时才会用 ffmpeg 转一道；出参里的「是否转过码」会如实告诉你走的哪条路。
- **抓字幕文本** —— 直接拿字幕转成纯文本（去时间轴、去重复行），优先人工字幕、没有就用自动生成的。
  要做摘要/检索时走这条：比「下载视频 → 语音转写」快一个数量级，也不花转写的钱。

## 常见用法

| 想做的事 | 怎么搭 |
|---|---|
| 频道选题监控 | 定时触发 → 取视频信息 → 抓字幕文本 → LLM 摘要 → 写进知识库 |
| 存档 | 下载视频（1080p）→ 存进对象库 |
| 只要内容不要画面 | 抓字幕文本；抓不到字幕再退回「下载（仅音频）→ 转写」 |

## 清晰度是怎么回事（不是转码）

YouTube 上一个视频本来就存着**多条流**：不同清晰度的视频轨、若干条音频轨。
下载站上那份「质量列表」就是把这些已有的流列出来让你点一个——不重新编码，也没法凭空
造出上游没有的清晰度。所以选清晰度是**免费**的，选哪个都只是下不同的文件。

本地真正会做处理的只有两件事：

| 事情 | 什么时候发生 | 代价 |
|---|---|---|
| **合并**（remux） | 上游没有该清晰度的单文件版时（约 360p 以上都是） | 只换容器不重编码，几秒；出参 `merged` 会标出来 |
| **转码** | 只在你把音频指定成 MP3/M4A/Opus 时 | ffmpeg 重编一遍，慢且是有损再压；出参 `transcoded` 会标出来 |

想要「不动一个字节的原始音频」就用**原样**；想要通用性最好的 MP3 就选 MP3，代价是那一道转码。

## 注意

- **默认限制 720p / 512MB，但上限不是必须的**：填 `0` 就是不限。
  平台侧的分块上传本身没有体积上限，真正的天花板是插件容器的磁盘与操作超时。
  默认给一个上限，是因为「不限」意味着第一个粘 4K 长视频链接的人就能把磁盘填满，
  而那种故障看起来跟下载毫无关系。超限时插件**直接报错而不是下到一半**——那样报错可读得多。
- **自动生成的字幕有错字**，用来做摘要没问题，用来引用原话要人工核对。
  输出里的「是否自动生成」会告诉你这一条。
- 下载受地区与登录状态影响：会员/年龄限制/地区限制的视频需要 cookies（见下）。
- 只下载你有权下载的内容。公开可看 ≠ 可任意再分发——YouTube 的服务条款与视频本身的
  版权是两回事，转载、二次分发前请自行确认。

## 获取账号最新发布

输入频道链接或 `@账号`，例如 `https://www.youtube.com/@YouTube` 或 `@YouTube`。
默认返回最近 10 条，可设为 1–50；发布类型可选「视频」「Shorts」「直播记录」。
每次只读取所选类型的频道列表，保留上游最近发布的顺序，不下载媒体，也不扫描全部历史。
不包含社区文字帖子。

输出 `videos` 数组，每项包含 `id`、`title`、`url`、时长、播放量、封面，以及上游提供的发布日期和直播状态。
频道列表不总是给出日期，缺失时 `upload_date` 为空；估算时间、权限和数值是否已知请看下方字段说明。
需要完整元数据时，将该项的 `url` 交给「取视频信息」。

监控示例：定时触发 → 获取账号最新发布 → 按视频 ID 与数据表中的记录去重 → 抓字幕 / 下载 → 保存 ID。
这个操作只返回当前列表；跨次去重由工作流维护，插件不保存监控状态。cookies 和代理使用同一套可选凭证。

## 列表字段与访问权限筛选

频道列表与全站搜索共用 `videos` 字段：视频 ID、标题、链接、频道名称/ID/链接、摘要、封面、时长、播放量、直播状态，以及下列字段。摘要可能截断。

| 字段 | 含义 |
|---|---|
| `availability` | `public` 公开；`subscriber_only` 频道会员专享；`premium_only` Premium；`private` 私密；`unlisted` 不公开列出；`needs_auth` 需登录；`unknown` 未知 |
| `published_at` | 从“几天前”等相对时间估算的 ISO 8601 UTC 时间；可能有数天甚至更大的误差，缺失为空 |
| `published_time_precision` | `approximate` 估算；`date` 仅日期；`unknown` 未知 |
| `upload_date` | 上游提供的 YYYY-MM-DD 日期；可能是估算值，须结合精度字段，缺失为空 |
| `release_at` | 上游提供的直播/首映时间，ISO 8601 UTC；可能在未来，与上传时间不同 |
| `duration_known` / `view_count_known` | 为 false 时，对应数值 0 只是兼容旧版本的缺省值，不是真实统计值 |

`access_filter` 支持 `all`（全部，默认）、`public`（仅明确公开）、`members_only`（仅明确会员专享）。**没有会员标记不代表明确公开**：很多频道和搜索结果不提供公开标记，因此 `public` 可能返回空列表，即使浏览器能播放。权限未知、Premium、私密、未列出和需登录的视频都不会混入“仅公开”。会员标记也不保证当前凭证有权观看。

筛选时最多检查 `scan_limit` 条上游条目（默认 50，范围 1–50，不能小于 `limit`），保持原顺序后最多返回 `limit` 条。不会无限翻页来凑数量。`scanned_count` 表示已检查的有效且不重复的视频数，`unknown_access_count` 表示其中权限未知的数量，`count` 是实际返回数；都不是频道或全站总数。未出现在上游列表的会员视频无法凭空补入。

例如：`{"channel":"@YouTube","access_filter":"members_only","limit":10,"scan_limit":50}`。匿名调用可能看不到会员列表；需要时选择有访问权账号的 cookies 凭证。筛选不会绕过观看权限。

## 全站搜索视频

使用 `search`，输入 `query` 关键词（1–500 字符），无需指定频道，例如 `{"query":"Python 入门","limit":10}`。返回跨频道的视频结果，不包含频道、播放列表或社区文字帖子，也不下载媒体。关键词中的链接只作为搜索文字，不会作为下载地址执行。cookies 和代理复用已有可选凭证。

`sort=relevance` 默认保留上游相关度顺序。`sort=date` 在 `scan_limit` 范围内按可用发布时间从新到旧排列，未知时间排最后，再截取 `limit` 条。上游可能忽略日期排序参数，且列表时间可能只是估算；**本批排序不代表全站最新，也不是精确时间排序**。访问权限筛选与字段含义同上；不会为每条结果额外请求播放器详情。

## 配置可选凭证

从插件详情的凭证入口新建 YouTube 凭证，填写后绑定到接入组，或在试调用、工作流节点中选择它。

- **登录 Cookies**：粘贴 Netscape 格式 `cookies.txt` 的完整内容，不是文件路径，也不是浏览器请求里的 Cookie 请求头。输入框会保留换行，保存后按密文显示。
- **代理地址**：选填插件进程可访问的代理 URL，例如 `http://proxy.example.com:7897`；支持含账号密码的地址，按密文保存。

两项均可选：不绑定凭证仍可匿名调用。每项非空凭证配置优先于对应环境变量；空值继续使用
`YTDLP_COOKIES`（文件路径）或 `YTDLP_PROXY`。共享副本的部署配置会供所有未覆盖该字段的调用使用。
每次提取使用独立的 cookies 临时文件，结束后删除，不把刷新后的 cookies 回写到平台凭证。

按 [yt-dlp 官方导出说明](https://github.com/yt-dlp/yt-dlp/wiki/Extractors#exporting-youtube-cookies)
导出 YouTube cookies；不要在聊天、日志或工作流普通参数中传递。cookies 失效后在凭证里更换即可，无需重启副本。
出现登录验证时，检查 cookies 有效性和代理出口；配置凭证不保证消除上游风控。

「凭证体检」检查 cookies 格式、ffmpeg、Deno、EJS 和代理出网。体检通过不代表已验证登录会话；保存后用
目标视频执行「取视频信息」试调用确认。

## 官方目录与部署

本插件的官方目录标识为 `sokel/youtube`，提供视频下载、音频下载、元数据和字幕。
`youtube-transcript` 是另一款字幕插件，操作和文件能力不同。

发布后从目录安装本插件，创建接入组，将目录提供的固定版本镜像与接入组 token 用于启动副本：

```bash
docker run -d --restart unless-stopped \
  -e SOKEL_ENDPOINT=https://sokel.example.com \
  -e SOKEL_TOKEN=skp_xxx \
  ghcr.io/sokel-dev/sokel-plugin-youtube:0.4.1
```

优先在平台凭证里配置 cookies 和代理。兼容已有部署环境变量：`YTDLP_COOKIES` 必须指向可写文件，
因为 yt-dlp 会回写 cookies；若使用只读挂载，启动时先复制到权限为 `0600` 的临时文件，再将变量指向副本。

## 列表成功但详情或下载失败

频道列表只读取发布列表；视频详情和下载还需要解析播放器及媒体地址。镜像必须包含 Deno JavaScript 运行时和与 yt-dlp 匹配的 EJS 脚本；官方镜像已包含，源码部署请安装 Deno 并用 `pip install -r requirements.txt` 安装完整依赖。先运行体检，缺少依赖会明确报错。

提取失败会显示脱敏后的上游原因。若仍要求登录验证，请检查所选凭证中的 cookies 是否有效、是否能访问目标视频，以及插件代理出口；列表成功和体检成功都不证明视频可下载。
