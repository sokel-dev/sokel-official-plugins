# PocketBase

将工作流连接到已有的自托管 PocketBase 实例中的记录。本插件提供七项操作，无需托管账户，使用 PocketBase 0.41.1 文档中的常规记录 REST API。PocketBase 尚未达到 1.0；升级服务器前请阅读上游迁移说明。

## 部署与凭证

将必填的部署环境变量 `SOKEL_POCKETBASE_URL` 设置为服务根地址，例如 `http://pocketbase:8090` 或 `https://internal.example/pocketbase`。不要包含 `/api`、凭证、查询参数或片段。支持内网 HTTP 地址和反向代理路径前缀，不会回退到公共服务。插件容器内的 `localhost` 指向插件容器自身，而非宿主机或 PocketBase 容器；请使用可达的服务名称或宿主机地址。

在插件凭证中，将 **访问令牌** 设置为已有的认证记录令牌，不要添加 `Bearer` 前缀。PocketBase 要求将令牌直接放在 `Authorization` 请求头中。请在插件外获取和续期令牌。使用仅具备所需集合权限的普通认证记录，不要使用超级用户令牌。本插件不执行登录、刷新令牌、管理集合、签发令牌，也不开放以 `_` 开头的系统集合。

集合规则分别控制列表、查看、创建、更新和删除权限。有效令牌并不代表可以执行所有操作。规则隐藏数据时，PocketBase 可能有意返回空列表或 HTTP 404，因此空结果并不能证明该记录对所有用户都不存在。

**检查服务可用性** 调用公开的 `/api/health` 端点。`ok=true` 仅确认服务返回可识别的健康响应，不验证令牌或集合权限。请对目标集合执行读取操作来验证访问权限。配置、网络或 HTTP 失败时，返回 `ok=false` 和简洁说明。

## 操作

| 操作 | 输入与结果 |
| --- | --- |
| `health_check` | 检查配置的服务，返回 `ok` 和 `message`。 |
| `list_records` | 输入集合 ID 或名称及可选查询设置；返回强类型记录包装、字符串形式的精确总数、`has_more` 和 `next_page`。 |
| `find_record` | 输入集合和必填筛选表达式，可选排序及关联展开；返回 `found` 与包含零条或一条记录的 `records`。 |
| `get_record` | 输入集合和记录 ID，可选关联展开；返回一条记录。 |
| `create_record` | 输入集合和 `data_json`；创建一条记录并返回创建结果。 |
| `update_record` | 输入集合、记录 ID 和 `data_json`；修改所提供的字段并返回更新结果。 |
| `delete_record` | 输入集合和记录 ID；只有收到正文为空的 HTTP 204 后，才返回 `deleted=true`。 |

集合名称及 ID 只能包含字母、数字、下划线或连字符，首字符必须是字母、数字或下划线，长度不超过 128 个字符。不支持以 `_` 开头的集合名称。记录 ID 保持字符串形式，并遵循同样的字符和长度限制。

## 读取与分页

`list_records.options` 接受 `page`（默认 1，最大 1000000）、`per_page`（默认 30，范围 1–200）、`filter`、`sort` 和 `expand`。筛选、排序和展开值均为不超过 8192 字节的单行字符串。筛选使用 PocketBase 原生表达式语法，例如 `enabled=false && title~"report"`。排序可使用 `-created,id`；服务器允许相关关联时，展开可使用 `author,author.team`。插件不会插入筛选变量：动态字符串需要按照 PocketBase 语法正确添加引号及转义。

每次调用只请求一页。`has_more=true` 时，使用 `next_page` 再次调用，并保持集合、页大小、筛选、排序和展开设置一致。`has_more=false` 时停止，此时 `next_page=0`。请求显式设置 `skipTotal=false` 以获取总数。插件会检查返回的分页元数据，对不一致结果报错，而不会误报读取完成。分页不是快照：翻页期间的数据写入或权限变化可能导致重复或遗漏。尽量使用以 ID 作为次级排序的稳定顺序，并按需要对 ID 去重。

`find_record` 使用提供的筛选条件请求第一页的一条记录；可能存在多个匹配项时，请设置排序。没有匹配项时返回 `found=false` 和 `records=[]`，不会构造空记录。关联展开仍受服务器查看规则限制。

## 动态字段值

记录包装暴露 `id`、`collection_id`、`collection_name` 和 `json`。完整记录使用 JSON **字符串**，原因是各集合具有不同的动态结构，且 JSON 数字可能超出工作流浮点数的精确表示范围。插件保留 ID 和 `9007199254740993` 这样的数字文本。服务器实际存储的精度仍由 PocketBase 字段类型和 SQLite 存储决定。

创建和更新时，请提供 JSON 对象字符串，例如：

```json
{"title":"Quarterly report","enabled":false,"rank":0}
```

显式的 `false`、`0` 和 `null` 会原样发送。创建时，若服务器默认值足够，可以使用 `{}`，也可以指定有效的字符串 `id`。更新至少需要一个字段，且不能修改 `id`。两类请求都不能设置 `collectionId`、`collectionName` 或 `expand`。其他字段由集合结构校验。PATCH 仅更新提供的字段；省略字段和显式传入空值含义不同。

本版本仅支持 JSON 记录，不上传文件、下载受保护文件、批量修改、订阅实时事件或管理集合。这些任务请使用 PocketBase 自身工具完成。

## 限制与失败处理

请求限制为 1 MiB，响应限制为 8 MiB，每次 HTTP 请求最长 45 秒。插件拒绝重定向，仅向配置的服务源站及路径前缀发送令牌。插件不会自动重试写入或轮询，也不会将修改请求正文标记为可重放。超时或连接失败后，请先检查记录再手动重试创建或更新，因为服务器可能已完成修改。

HTTP 错误只报告状态和安全提示，不回显上游响应正文、令牌或内部 URL。HTTP 401 通常表示需要更换令牌；HTTP 403 或 404 可能与集合规则有关。HTTP 429 会给出有界的重试等待时间。即使 HTTP 请求成功，缺少或不匹配的记录元数据也会被视为错误。
