# TuShare Pro

券商研报增量 + 221 个 TuShare 目录接口。**只负责取数**——不落库、不去重、不加工。

## 凭证

| 字段 | 说明 |
|---|---|
| `token` | **必填**。tushare.pro 个人主页里的接口 TOKEN |
| `base_url` | 留空用官方地址 |

填完点凭证行的 **「检查」**：它打一次门槛最低的接口（120 积分档），说明里照抄 TuShare 的原文——
「您的token不对，请确认。」要换 token，「没有访问该接口的权限」是积分不够，两者只能靠这句话分辨。

⚠️ **TuShare 按积分给权限**：每个接口都有积分门槛（研报类 2000 分起，部分 5000 分）。
积分不够时它在 HTTP 200 的信封里回错误码——插件把这类业务错误翻成报错，
**不会当成空数据让游标照常前进**（那会静默丢掉一整段）。

## 两条增量流

| 操作 | 说明 |
|---|---|
| **券商行业研报增量** | 按交易日拉，一次一天 |
| **券商个股研报增量** | 同上 |

出参：`items` / `synced_date` / `next_cursor` / `has_more` / `count`。

**每条记录带 `dedup_key`**：TuShare 的研报**没有主键**，插件取「交易日期+股票代码+机构+标题」
的摘要——回补重跑同一天必须得到同一个键，否则回补一次就多一份。

## 增量与回补

```
[定时触发] → [数据表·取游标] → [研报增量] → [随便你接下游] → [数据表·写回游标]
```

追平昨天后 `next_cursor` 停在当天反复拉——当天的研报还在陆续入库，反复拉同一天是对的。

`lookback_days` 是「**追平之后退一次**」：追平昨天后游标退回「昨天 − 回补天数」，
下一轮定时从那儿重扫，把晚几天补录的研报捞回来。**它不从游标上减**——
那样游标每轮净退 (回补 − 1) 天，越同步越旧（修过的坑）。默认 0。

## 221 个目录接口

TuShare 文档站的接口**全部生成了契约**，**默认全部可用**；
要收窄用 `TUSHARE_APIS` 环境变量（`TUSHARE_APIS=stock_basic,daily,fina_indicator`，`none` 一个都不开）。
全开会让画布的节点选择器没法看，也没人真的要用满 221 个。

## 坑

- **按上海时间切天**：TuShare 的 `trade_date` 是交易所本地日期、没有时区标注，
  跑在 UTC 机器上按本地时间算会整体差一天。
- **积分不够的接口调用会失败**，不是空数据——先在 tushare.pro 上确认你的积分档位。
