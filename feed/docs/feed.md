# Feed 订阅（feed）

从一个来源拉新条目，产出**统一形状的 JSON**。换来源不用改下游节点。

## 来源

| 来源 | 「目标」填什么 | 要凭证吗 |
|---|---|---|
| **RSS/Atom 地址** | 完整的 feed 地址 | 不要 |
| **雪球 · 某用户的动态** | uid（主页地址 `xueqiu.com/u/<这一串>`，直接粘整个地址也行） | 不要（插件自取匿名令牌） |
| **雪球 · 热帖** | 留空 | 同上 |
| **雪球 · 快讯** | 留空 | 同上 |
| **财联社 · 电报** | 留空 = 全量电报流；也可填一个分类 | 不要（插件自己算签名） |
| **东方财富 · 关键词搜索** | 关键词（某只票的名称或代码） | 不要 |
| **金十数据 · 快讯** | 频道号（留空 = 全部快讯） | 不要（插件带固定请求头） |

## 出参：一条内容长这样

```json
{
  "id": "...", "title": "...", "url": "https://...",
  "summary": "纯文本摘要（已去 HTML，最长 500 字）",
  "content_html": "来源给的正文（RSS 常常只有摘要）",
  "author": "...", "published_at": "2026-08-19T02:00:00Z",
  "source": "xueqiu_user:1234", "tags": [], "images": [],
  "dedup_key": "..."
}
```

`dedup_key` 用来在下游落库时 upsert——与本平台其它取数插件同一条约定。

## 增量怎么用

```
[定时触发] → [数据表·取游标] → [取内容] → [随便你接下游] → [数据表·写回游标]
```

游标是**不透明串**，原样存回数据表即可，别去解析它。`has_more` 为真表示这批拉满了，
应当**立刻再拉一次**而不是等下一个定时。

**第一次拉（游标为空）只取最近一批，不回溯全部历史**——接一个发了十年的源，
工作流会被几千条瞬间冲垮。

> 游标长这样：`2026-08-19T08:35:52Z|2ceab3c4,6bb9e374,…`，
> 里面同时装了「最新时间戳」和「最近见过的 id」。只看时间戳会漏掉同一秒发的第二条
> （快讯类源一秒好几条是常态），只看 id 集合会无限膨胀。两者合起来才既不漏也不重。

## 凭证（多数情况留空）

| 字段 | 什么时候要填 |
|---|---|
| 雪球 Cookie | 匿名令牌被风控挡住时，粘一条浏览器里的整条 Cookie |
| User-Agent | 想与你取 cookie 的浏览器保持一致时 |
| 出站代理 | 取境外源时 |

## 关于「更多来源」

现在覆盖两种取数方式：**标准 feed**（RSS/Atom）与**站点 JSON 接口**（雪球、财联社）。
还有一类站点既没有 feed 也没有 JSON 接口，只能解析网页——那类**暂时不在这个插件里**，
画布上用「HTTP 请求」+「HTML 提取」两个节点拼出来即可，效果一样。

## 常见问题

**「解出来一条内容都没有」**——那个地址多半不是 feed（是网页）。RSS 地址常在页面底部的
「订阅」链接里，或者试试 `<link rel="alternate" type="application/rss+xml">`。

**中文乱码**——插件已处理 GBK/GB2312 的源；仍乱码的话把地址给开发者看一眼。

**雪球取不到内容**——匿名令牌被挡了，按上面说的粘一条 Cookie。

**金十一条都拉不到**——它的两个门槛请求头（`x-app-id` / `x-version`）随对方前端升级会变，
插件会明说是这个原因，改两个常量即可。

**财联社一条都拉不到**——多半是它的签名参数变了（版本号 `sv`）。这时插件会明说
「可能是签名变了」而不是装作「没有新内容」；把这条报给开发者，改一个常量就好。

**时间是空的**——来源没给可解析的时间。插件**不猜**，因为猜错会让游标跳过真实的新条目；
这类源的去重完全靠 id，功能不受影响。
