# 友盟推送（U-Push）

App 推送的友盟通道：按设备 token 单播/列播，或全量广播。与「阿里云」插件的
移动推送互补（双通道推送架构里各推各的设备池）。

## 一、准备凭证

[友盟控制台](https://message.umeng.com/) → 应用管理。**Android 与 iOS 是两个应用**，
各有一对 AppKey / Master Secret——把用到的平台那组填进凭证（只推一端就配一端）。

## 二、用法

- **推送**：`device_tokens` 多个逗号分隔（≤500）；**留空 = 全量广播**（想清楚再发）。
  Android token 44 位、iOS 64 位十六进制。`production` 关掉时 iOS 走测试证书环境。
- **查任务状态**：广播/列播返回任务 ID，可查下发数/打开数。
  **单播是消息类推送，友盟不提供任务统计**（返回的是 msg_id）——这是友盟的约定。
- **撤销任务**：只能撤还没开始发的（定时/排队中）。

## 三、排错

| 报错 | 处理 |
|---|---|
| 友盟不认这个请求 | AppKey/Master Secret 核对；Android 与 iOS 是两个应用别混 |
| device_token 不合法 | Android 44 位 / iOS 64 位 hex；别把别家推送的 token 填进来 |
| iOS 收不到 | production 与打包证书环境要一致；检查友盟控制台的 iOS 证书配置 |
| Android 收不到 | 厂商通道（华为/小米…）要在友盟控制台配好；纯友盟通道杀后台收不到是常态 |
