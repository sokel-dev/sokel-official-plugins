# Elasticsearch

把 ES 接进工作流：查日志与文档、灌数据、管索引。**ES 7 / 8 / 9 与 OpenSearch 都支持**——
插件走标准 REST 接口，不锁客户端版本。

## 一、准备凭证

| 字段 | 怎么填 |
|---|---|
| 地址 | 集群地址带协议与端口，如 `https://es.internal:9200`。多节点填其中一个即可 |
| 用户名 / 密码 | basic 认证（ES 8 默认账号 `elastic`）|
| API Key | Kibana → Stack Management → **API Keys** 生成的 encoded 值。填了它就不用用户名密码；**更推荐**：能按索引限权、能单独吊销 |
| 跳过证书校验 | 自建集群用自签证书时选 `on`（连接仍加密，但不校验对端身份）|

配好点「检查凭证」：通了会显示发行版、版本、集群名与集群状态
（`green` 都好 / `yellow` 副本没分配，单节点是常态 / `red` **有主分片丢了，数据不全**）。

## 二、挑哪个操作

| 想做的事 | 用 | 说明 |
|---|---|---|
| 查文档 | 搜索 | **查询** 收 Query DSL 原文；**简式查询** 收 Lucene 一行式（`status:error AND host:a1`）|
| 只要个数 | 统计条数 | 它的数是精确的（搜索的总数不一定，见坑）|
| 算分布/趋势 | 搜索 + 聚合 | 取几条留空 = 只回聚合不回文档 |
| 按 ID 存取 | 取 / 写入 / 更新 / 删除文档 | 更新是局部改，写入是整篇覆盖 |
| 灌一批数据 | 批量写入 | 一个请求写多篇，比逐条快一个量级 |
| 清理过期数据 | 按查询删除 | **必须给查询**（不给等于删光索引）|
| 管索引 | 索引列表 / 建索引 / 删索引 / 看字段定义 / 加字段定义 | |
| 换字段类型 | 建索引 → 重建索引 → 切别名 | ES 不能改已有字段的类型，这是唯一路径 |
| 其它接口 | 通用调用 | `_tasks`、`_ilm`、`_snapshot`、`_sql`… |

排序填 `@timestamp:desc` 这种 `字段:方向` 形态，可以给多个（先给的优先）。
字段特别多的索引，用「只取这些字段」能省掉大量带宽。

## 三、幂等：别把重跑写成重复数据

工作流会重试、会被重复触发。**拿业务主键当文档 ID**，重跑就是覆盖同一篇：

- 写入文档 → 填「文档 ID」
- 批量写入 → 填「拿哪个字段当 ID」（如 `sku`、`order_id`）

不给 ID 时 ES 每次都生成一个新的，同一批数据跑两遍就有两份，而且很难发现。

## 四、坑

- **命中总数默认只精确到 10000**：超出时 ES 回的是下界，出参 `总数是下界` 会是 `true`。
  要准确总数就打开「精确总数」（更慢），或改用「统计条数」。
- **写完不是立刻能搜到**：ES 默认约 1 秒后才刷新可见。写完马上查却查不到多半就是这个。
  单条要立刻可见就开「立即可搜」，**别在批量循环里开**——每次强制刷新分片，很慢。
- **已有字段的类型改不了**（ES 硬限制）。路径是：建新索引（带新 mapping）→ 重建索引 →
  切别名。查询方一直用别名，切换对它无感知。
- **`text` 字段不能直接聚合/排序**，要用 `.keyword` 子字段（`host` → `host.keyword`）。
  不确定就先「看字段定义」。
- **批量写入是部分成功的**：几条失败不会让整批回滚。出参给了 `成功条数`/`失败条数`/`失败原因`，
  **流程里记得判失败条数**，别只看有没有报错。
- **分页最多翻到第 10000 条**（`from + size` 的硬上限）。要全量导出用重建索引，
  或用通用调用走 `search_after` / PIT。
- **危险操作有闸**：按查询删除必须给查询；删索引不接受 `*` 和 `_all`。插件会直接拒绝
  并告诉你该用哪个操作——这是刻意的，这两个接口在 ES 那边字面上都支持「全都删」。
