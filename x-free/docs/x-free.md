# X（免费读写）

使用已登录 X 账号的 Cookie 搜索和读取推文、获取账号的 Lists 和 List 时间线、维护 List 成员、查看用户资料、发布文本、回复与删除推文，无需申请官方 API Key 或购买官方 API 套餐。插件基于开源 TweetKit，使用 X 网页接口；免费指不收取官方 API 调用费，自行部署仍可能产生服务器或网络费用。

本文对应 v0.2.1，沿用 v0.2.0 的 11 项操作及输入输出字段。

## 配置凭证

1. 在浏览器中正常登录你有权使用的 X 账号，打开 `https://x.com`。
2. 打开开发者工具 → Application（应用）→ Cookies → `https://x.com`。
3. 分别复制 `auth_token` 和 `ct0` 的值，填入插件凭证的「登录令牌」和「CSRF 令牌」。两者必须来自同一次登录会话，不要粘贴整个 Cookie 请求头。
4. 按需填写插件进程可访问的代理地址。容器内的 `127.0.0.1` 指向容器自身；Docker Desktop 访问宿主机代理通常使用 `host.docker.internal`。
5. 点击「测试」。测试只读取时间线，不发布内容；成功说明本次只读请求通过，不代表账号拥有所有写入权限。

Cookie 等同于登录凭据，只保存在平台凭证中，不要写进工作流参数、日志或公开仓库。该插件不使用账号密码登录，不自动处理验证码或切换账号。

## 使用

- **搜索推文**：例如 `from:某账号 关键词`，按最新顺序获取匹配结果。
- **获取用户推文**：输入账号名（可带 `@`），读取最近的推文。
- **获取我的 Lists**：读取当前凭证账号创建和关注的 Lists，排除推荐列表，根据名称选择目标并取得 ID。
- **获取 List 推文**：输入 List 链接或 ID，读取一页推文；通过返回的游标继续向历史翻页。
- **添加 List 成员 / 移除 List 成员**：输入 List 链接或 ID 和用户账号，维护你有管理权限的 List 成员。
- **获取推文 / 获取用户资料**：分别按推文 ID、账号名查询。
- **发布或回复推文**：填写正文；「回复目标 ID」留空则发布新推文，填写则回复该推文。
- **删除推文**：填写当前账号有权删除的推文 ID，删除后无法撤销。

搜索推文和获取用户推文默认返回 20 条，最多请求 100 条；X 可能返回更少结果。这两项操作提供有界的最近批次，不提供历史归档或跨调用分页游标；定时监控时请按推文 ID 去重。获取 List 推文的分页规则见下文。凭证体检通过只读时间线请求检查登录和网络，不发帖。当前不提供媒体上传、私信或实时事件触发。

## 查找我的 Lists

不知道 List ID 时，先选择「获取我的 Lists」（`my_lists`）。该操作使用当前凭证账号读取 X 列表管理页中创建和关注的 Lists，排除推荐模块，不仅限于自己创建的 List。根据返回的名称（`name`）选择目标，将其 `id` 传给「获取 List 推文」即可。

每次调用只请求一页。输入「每页请求条数」（`limit`，1 到 100，默认 20）和可选的「分页游标」（`cursor`）；首次留空，后续用本次返回的 `next_cursor` 继续翻页。插件返回完整一页，实际数量由 X 决定。返回的 `lists` 包含各 List 的 `id`、`name`、`description`、`mode`（`public` / `private`，未知时为空）、`member_count`、`subscriber_count`、`owner_id`、`owner_username` 和 `url`，同时返回实际数量 `count`、下一页游标 `next_cursor` 和可继续翻页标记 `has_more`。空页带有游标时仍可继续翻页。该操作不创建或修改 List。

列表封面加载失败或页面出现空模块时，只要列表数据有效，仍可正常读取。登录失效、限流和列表数据缺失仍会报错。

## 维护 List 成员

通过「获取我的 Lists」选定目标后，可使用「添加 List 成员」（`add_list_member`）或「移除 List 成员」（`remove_list_member`）。填写「List 链接或 ID」（`list_id`，格式同下文）和「用户账号」（`username`，可带 `@`，不要填个人主页链接）。凭证对应的账号必须有该 List 的管理权限；能读取一个 List 不代表能修改其成员。

这两项操作每次只处理一个账号，不自动批量添加或移除成员。它们维护 List 中的账号成员，不是关注或取关 List。成功时返回 List ID（`list_id`）、目标用户 ID（`user_id`）、用户账号（`username`）和操作成功标记（`changed`）。`changed` 表示 X 已接受操作，不代表该账号此前一定不在或已经在 List 中，也不能据此判断首次发生了成员变化。

失败不会自动重试；工作流中的这些写入节点也应关闭自动重试。遇到超时或连接中断，先在 X 中检查 List 成员状态，再决定是否重试。插件不创建 List，请先在 X 中创建。

## 获取 List 推文

在工作流中选择「获取 List 推文」（`list_timeline`）；可以使用「获取我的 Lists」返回的 ID，也可以直接输入已有的链接或 ID。获取我的 Lists 和获取 List 推文是只读操作，不修改成员。私有 List 仅在凭证对应的账号有访问权限时可读。

| 输入 | 说明 |
| --- | --- |
| List 链接或 ID（`list_id`） | 数字 ID，或 `https://x.com/i/lists/<id>`；也接受 `https://twitter.com/i/lists/<id>`。 |
| 每页请求条数（`limit`） | 1 到 100，默认 20。这是请求页大小，X 可能返回更多或更少；为避免截断后跳过数据，插件返回整页，不按该值截断。 |
| 分页游标（`cursor`） | 可选；首请求留空，后续填入本轮上一次返回的 `next_cursor`。 |

每次调用只请求一页，返回以下字段：

| 输出 | 说明 |
| --- | --- |
| 推文列表（`posts`） | 本页解析出的完整推文列表。 |
| 返回数量（`count`） | 实际返回的推文数量，可能与每页请求条数不同。 |
| List ID（`list_id`） | 从输入解析得到的数字 ID，按字符串返回。 |
| 下一页游标（`next_cursor`） | 用于本轮补拉中向历史翻页的游标。 |
| 可继续翻页（`has_more`） | 是否返回了可继续使用的下一页游标；不表示下一页一定有推文。 |

空页仍可能带有下一页游标，不能仅凭 `posts` 为空或 `count` 为 0 判断已经拉完。游标不是下次定时任务的新推文检查点；每次定时任务都应从空游标重新读取最新一页。

## 定时拉取 List

先用「获取我的 Lists」按名称选定目标 ID，再按「流程定时器 → 获取 List 推文 → 数据表幂等写入 → 按需继续翻页」搭建工作流。以下规则用于减少重复与遗漏，不能保证零漏报或历史完整性。

1. **确定首轮范围**：首次运行建议建立当前基线，或明确要追溯的时间范围；不要默认首次就遍历全部历史。
2. **从最新页开始**：每轮定时任务将 `cursor` 留空。每 10–15 分钟可作为配置起点，但不保证不会触发限流；根据 List 活跃度、实际页数和 X 的响应调整。
3. **幂等写表**：以返回的 `list_id` 和每条推文的 `id`（存入表中的 `post_id`）组成联合主键，重复记录执行更新或忽略。两个 ID 都按字符串保存，避免大整数精度丢失。
4. **在本轮内补拉**：将 `next_cursor` 传给下一次调用，逐页向历史读取。遇到上次完整完成范围中的记录后，可继续保留少量重叠页，并逐条按 ID 去重；转帖和乱序结果可能包含尚未处理的旧 ID，不能只比较最大推文 ID，也不宜遇见第一条旧记录就立即结束。空页带有游标时仍按相同规则继续。
5. **设定边界和失败通知**：设置每轮最大翻页数和失败通知。按已处理记录边界与重叠策略结束，或上游不再提供下一页游标时，才将本轮标记为完成并推进已完成检查点。若达到最大翻页数、遇到 429 限流、401 登录失效或其他错误，保留已写入的数据，但不要推进已完成检查点；修复后从最新页重新补拉并依靠联合主键去重，避免把未处理区间跳过。

检查点用于记住上次完整完成的范围，不能替代数据表中的逐条 ID 去重；失败轮次中部分写入的记录也不能作为已完成边界。List 成员、推文可见性和网页接口都可能变化，接口也可能不返回全部历史；需要完整归档时不能依赖此操作作出完整性保证。

## 错误与限制

- **登录失效 / 账号受限**：先在浏览器中确认账号可用，再更新同一会话的两个 Cookie。
- **请求过于频繁**：减少调用频率，等待限流解除；插件不会通过切换账号绕过限制。
- **网络错误**：检查代理是否可被插件进程访问。
- **无 List 管理权限**：确认凭证账号有权添加或移除该 List 的成员；可读取或关注 List 不等于可管理。
- **网页接口发生变化**：更新插件版本；网页接口没有官方兼容性承诺，不能保证持续可用。
- **发帖超时或连接中断**：先在 X 中检查是否已经发布，再决定是否重试。插件不会自动重试写入；工作流节点也应关闭自动重试，以免重复发帖。

网页自动化可能触发验证、锁定或账号限制。建议先用获授权的测试账号低频验证。无需官方 API 套餐不等于匿名访问或无限额度。
