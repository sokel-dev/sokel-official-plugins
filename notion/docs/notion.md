# Notion

读写 Notion：搜索、查表、建页、改正文（markdown）、评论、文件，并可作为**事件源**——
数据源里新增行 / 行被修改时触发工作流。

## 第零步：把插件进程跑起来

这是**自部署插件**：平台只有它的目录条目，进程要你自己跑（跑在哪都行，只要能连上 broker
和 Notion）。在插件页复制接入命令，或者：

```bash
docker run -d --name notion --restart unless-stopped \
  -e SOKEL_ENDPOINT=https://<平台地址> \
  -e SOKEL_TOKEN=skp_xxx \            # 插件页 → 接入组 → 「接入命令」里复制
  ghcr.io/sokel-dev/sokel-plugin-notion:latest
```

起来后日志里会有一行 `已接入平台：插件「Notion」就绪`，插件页的接入组随即显示副本在线。
**没有这一步的话，画布上这个插件一个操作都调不通**（凭证配得再对也没用）。

⚠️ 事件源是增量轮询、游标存在凭证里，所以**建议单副本**——多副本会各自推进同一个游标，
造成重复推送与游标来回跳。

## 第一步：让集成看得见你的页面（**最高频的坑**）

Notion 的集成默认**什么都看不到**，哪怕令牌是对的。没做这一步的表现是所有操作都报
「找不到或没权限访问该对象」，而 Notion 的原文只说 "Could not find page with ID ..."，
看起来像 id 抄错了。

在 Notion 里打开那一页（或那个数据库）→ 右上角 **「⋯」→「连接」→ 添加你的集成**。
子页面会自动继承，所以通常给一个顶层页面授权就够了。

## 第二步：凭证（两种认证，二选一）

**A. 内部集成密钥**（自己部署最省事）

1. 打开 <https://www.notion.so/profile/integrations> → 「新建集成」
2. 类型选「内部」，选好工作空间，能力勾上「读取内容 / 更新内容 / 插入内容」（要评论再勾评论）
3. 在「密钥」页复制 **Internal Integration Secret**（`ntn_` 开头），填进凭证的「内部集成密钥」

**B. OAuth 授权**（多人用、或不想让人碰密钥时）

凭证的三个令牌字段**全部留空**，直接点凭证行的 **「授权」**，在 Notion 的同意页上勾选
要交给它的页面，回来即可用——`access_token` 由平台写入，手填只会把它弄坏。

这条路需要**平台管理员先配一次**（一次配好，之后所有人建凭证都能直接点授权）：

1. <https://www.notion.so/profile/integrations> 里那个集成 → 类型改成 **「公开」（Public）**
2. 填上 **Redirect URI**，值必须与平台的回调地址**一字不差**：

   ```
   <平台地址>/api/v1/credentials/oauth/callback
   ```

   开发期与正式域名是**两条**，各自登记（`http://localhost:5173/...` 与 `https://你的域名/...`）。
   差一个字符就是换码时报 `redirect_uri_mismatch`。
3. 把该页给的 **OAuth client ID / client secret** 配进平台后端的环境变量，然后重启后端：

   ```bash
   NOTION_OAUTH_CLIENT_ID=...
   NOTION_OAUTH_CLIENT_SECRET=...
   NOTION_OAUTH_REDIRECT_URL=https://你的域名/api/v1/credentials/oauth/callback   # 与第 2 步同一个值
   NOTION_OAUTH_PROXY=http://127.0.0.1:7897    # 选填：平台连不上 Notion 时（境内部署）
   ```

   没配这几项时点「授权」会明确报 `平台未配置 Notion OAuth 应用`，不是静默失败。

**注意**：Notion 的公开集成里，「用户能给这个集成哪些页面」是用户在同意页上勾的，
**没有作用域（scope）可申请**——所以授权后能读到什么，取决于那个人勾了什么。

凭证行的 **「检查」** 读一次集成自己的身份，回集成名与工作空间——它只回答「令牌活着吗、
连的是哪个工作空间」，**不代表读得到某一页**：页面还得按上面第一步「连接」给这个集成。

两种都填时以密钥优先。

## 平台在境内时

Notion 在境外。连不上的表现只是「超时」，看不出是网络不通——在凭证的**出站代理**里
填 `http://127.0.0.1:7897` 这类地址即可（按凭证配，不影响平台其它出站）。

## 数据库 vs 数据源（2025 年 9 月起）

一个**数据库**是容器，里面挂一个或多个**数据源**（就是你看到的那张表）。
查询、建行、改表结构用的都是**数据源 id**。

- 单源库（绝大多数）：数据库链接直接贴进「数据源 ID」即可，插件会自动取里面那一个。
- 多源库：先用 **「列出数据源」** 拿到各个 id，再选一个——插件不会替你猜。

所有 id 字段都可以**直接贴完整的 Notion 链接**，插件会自己抠出 id（并且知道
`?v=` 后面那串是视图 id，不是数据库 id）。

## 属性怎么写

读出来的每一行有两份属性：

- `props`：归一化后的平铺值，直接可读可引用
  （文本 → 字符串，多选 → 字符串数组，日期 → `{start, end}`，人 → 名字数组，关联 → 页面 id 数组）
- `properties_raw`：Notion 原样的嵌套 JSON，`rollup` / `formula` 这类归一化会丢信息的去这里取

写入时给归一化的那种就行，插件按表结构自动包成 Notion 要的形状：

```json
{"状态": "进行中", "标签": ["报告", "已审"], "截止": "2026-08-20", "负责人": ["小明"], "完成": true}
```

几条要知道的：

- **列名写错 / 候选值不存在 / 这列是算出来的**，都会在发请求前就报出来，并列出有哪些列或候选值。
- `formula` / `rollup` / `创建时间` 这类是 Notion 算出来的，写不了。
- 清空某一列：给 `null`。
- 「负责人」这类人员列，**名字和用户 id 都认**（名字会自动去查一次成员表）。
- 标题不必写进 `props`——建页/改页都有单独的「标题」入参（每个库的标题列叫法不同）。

## 正文用 markdown

「读页面」给的是整页 markdown，「改页面正文」收的也是 markdown，三种改法：

| 模式 | 用途 |
|---|---|
| `append` | 追加到页面末尾（默认） |
| `replace` | 整页替换 |
| `edit` | 搜索替换：把 `old_str` 换成 `new_str`（**推荐给模型用**，比重写整页安全得多） |

markdown 表达不了的东西（数据库块、嵌入、看板）用「读子块 / 追加原始块」，那两个走 Notion 的原始块 JSON。

## 事件（数据源变动）

- 在**凭证**里填「监听的数据源」（逗号分隔的 id 或链接），留空 = 不产事件。
- 一个凭证一路轮询，默认 60 秒一轮；盯的表越多，间隔别调得越短（Notion 限流 3 次/秒）。
- 两个事件：**新增行** / **行被修改**（按创建时间与最后编辑时间是否几乎相同来分）。
- 第一次启动只从「当下」开始，**不会把历史行洗一遍**。
- 事件只带元信息与属性；要正文接一个「读页面」。

**要实时、或要页面正文/评论级的事件**：Notion 的 webhook 订阅只能在它的集成设置页手工建
（API 建不了），所以插件装不了。做法是——

1. 画布上放一个 **Webhook 触发**节点，复制它的地址；
2. Notion 集成设置 → Webhooks → 新建订阅，粘贴该地址；
3. Notion 会先往这个地址发一条带 `verification_token` 的请求，在平台的**运行记录**里找到它，
   粘回 Notion 的验证框；
4. 之后 23 种事件都会实时打过来。载荷里只有 `entity.id`，接一个「读页面」补内容。

## 限制

- Notion 的**搜索只匹配标题**，不搜正文。
- 单请求最多 100 个块、500KB；单个富文本 2000 字（插件会自动切段）。
- 上传文件单次上限 20MB。
- 页面只能移进**回收站**，API 删不掉。
- 过滤/排序用 Notion 的原生 DSL（原样透传），写法见
  <https://developers.notion.com/reference/post-database-query-filter>。
