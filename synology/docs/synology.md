# Synology 文件监听

监听 NAS 上的目录：文件新增 / 变更 / 删除时触发工作流；也可以读文件、列目录、移动、删除。

## 部署（这个插件必须跑在 NAS 上）

它靠 inotify 感知文件变动，而 **inotify 不穿网络文件系统**——所以插件必须与文件在同一台机器：

1. Synology 的 Container Manager 里用本仓库的镜像新建容器
2. 把要监听的卷目录 **bind mount** 进容器（如 `/volume1/research` → `/watch`）
3. 环境变量填平台地址与接入 token（`SOKEL_ENDPOINT` / `SOKEL_TOKEN`）

别人从 Windows/Mac 经 SMB 写入时，NAS 上的 smbd 在本地落盘，事件照常触发。
详见插件目录下的 README（含 Synology 的 inotify watch 上限调整）。

## 凭证 = 监听配置

一条凭证 = 一个受监听的子目录（多目录就建多条凭证）：

| 字段 | 说明 |
|---|---|
| **监听目录** | **容器内**的路径（挂载点之下），如 `/watch/研报入库` |
| 扩展名过滤 | 逗号分隔（`pdf,docx`）；留空 = 全部 |
| 忽略模式 | 逗号分隔子串；Synology 的 `@eaDir`/`#recycle` 等垃圾目录恒忽略 |
| 落定秒数 | 文件静默 N 秒且大小稳定才上报，默认 2 |

**落定秒数是必要的**：SMB 拷贝大文件时会先建一个临时文件再改名，
拷到一半就上报的话，下游读到的是半个文件。

配好点「检查凭证」：会看监听目录在不在、容器读不读得了，并报第一层条目数。
卷没挂上、或把宿主机路径当成容器内路径填了，这一步当场看得出来——
否则它的表现是「事件源一直不出事件」，最难自证的那种。

## 注意

- 所有操作的路径都被**限制在凭证的监听目录内**（防越界读写挂载卷的其它位置）。
- 事件只带元信息（路径/大小/时间），不带字节；要内容用「读文件」按需取——
  NAS 上常是视频和压缩包，几 GB 的东西不该塞进事件。
