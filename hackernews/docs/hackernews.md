# Hacker News

读榜单、帖子、评论，按关键词搜索；**有人评论你的帖子、或回复你的评论时触发工作流**。不需要注册任何东西，也不花钱。

**它不能发帖，也不能回复。** Hacker News 没有写接口，自动发帖还违反站规（会被封号）。所以这个插件的用处是
「别错过任何一条讨论」：评论一来就把内容和直达链接交给你的工作流，回复在 HN 网页上点链接去做。

## 配置

HN 读数据不需要登录，凭证只用来写**监听什么**（事件源是常驻的，它没有节点配置，只能从凭证里读）。
只用操作、不用事件的话，建一条空凭证就行。

| 字段 | 说明 |
|---|---|
| 监听的 HN 用户名 | 你的 HN 账号（区分大小写）。它最近发的帖子下有新评论、或有人回复它的评论时，触发「有新评论」 |
| 额外监听的帖子 | 帖子 id 或地址，多个用逗号分隔：别人替你发的帖子、你想跟进的讨论 |
| 监听的关键词 | 出现这个词的新帖子或新评论触发「关键词命中」：项目名、`github.com/你的/仓库`、官网域名 |
| 跟踪多少天内的帖子 | 默认 14。两周前的帖子偶尔还有人评论，再早的基本沉了 |
| 轮询间隔（秒） | 默认 120，最短 60 |
| 出站代理 | 部署环境在国内、连不上 news.ycombinator.com 时必填，如 `http://127.0.0.1:7897` |

建好后点「测试」：它会检查两个接口都能连上，并核对用户名是否存在。

## 事件

**有新评论**：下面三种情况都会触发，同一条评论只触发一次。
- 你最近发的帖子下有人评论（不管回复的是帖子还是帖子里别人的评论）；
- 「额外监听的帖子」下有人评论；
- 在别人的帖子里，有人直接回复了你的评论。

你自己写的评论不会触发。

| 字段 | 说明 |
|---|---|
| `comment_id` | 评论 id |
| `text` | 正文纯文本（去掉了 HTML，链接保留完整地址） |
| `text_html` | HN 返回的原文 HTML，一字不改 |
| `author` / `author_url` | 评论人和他的主页 |
| `url` | 这条评论的地址，**回复就点这里** |
| `story_id` / `story_title` / `story_url` | 评论所在的帖子 |
| `parent_id` | 回复的是哪一条：等于 `story_id` 表示直接回复帖子，否则是回复某条评论 |
| `is_reply_to_me` | 为真表示它直接回复了你写的帖子或评论（适合优先处理） |
| `created_at` | 发布时间，RFC3339，UTC |

**关键词命中**：新帖子或新评论里出现了监听的关键词。字段与上面类似，另有 `kind`（story / comment）、
`item_id`、`title`（帖子标题）、`link`（链接帖的外链）、`points`（帖子得分）、`matched_query`。

**多久能收到**：一个轮询间隔，加上 HN 搜索接口的收录延迟（通常一分钟以内）。第一次启用时不会把历史评论
全推一遍，只从启用那一刻往后算。

### 常见接法

- 评论写进数据表（按 `comment_id` 去重），在应用里做一个待回复列表；
- `is_reply_to_me` 为真的转成待办，附上 `url`；
- 交给大模型起草回复，你在 HN 上贴过去。

## 操作

| 操作 | 说明 |
|---|---|
| 取条目 | 按 id（或直接粘 HN 地址）读一条帖子或评论：得分、评论数、正文 |
| 取榜单 | 首页、最新、最佳、Ask HN、Show HN、招聘的前若干条（最多 100） |
| 搜索 | 按关键词搜帖子和评论，最新在前；可限定最近多少小时 |
| 取评论 | 一条帖子下的全部评论，按讨论顺序平铺，带层级；可只取某个时刻之后的 |
| 检查连接 | 两个接口能否连上，监听的用户名是否存在 |

## 限制

- 不能发帖、不能回复、不能投票（HN 没有写接口）。
- 评论没有公开分数，`score` 对评论恒为 0。
- 被删除或被标记为 dead 的评论不出现。
