# 群晖上传

把工作流里的文件上传到群晖 NAS 的文件夹，走 DSM 自己的 FileStation 接口，Synology Drive、Cloud Sync 和文件索引都能照常感知新文件。

## 和「Synology 文件监听」插件的区别

「Synology 文件监听」插件靠挂载目录工作：插件容器跑在 NAS 上，直接读写挂进去的目录。这个方式**写文件有一个坑**：容器写进挂载目录的文件，群晖主机收不到变更通知，**Synology Drive / ShareSync 不会同步它**——文件在磁盘上，但要等有人在主机上碰一下它、或重启 Drive 才会被发现。

本插件改为用 DSM 账号登录、通过网页接口上传，等同于在 File Station 里上传，不存在这个问题。它也不需要挂载目录，部署在任何能访问到 NAS 的地方都行。

需要监听 NAS 上的新文件，仍用「Synology 文件监听」；需要往 NAS 上放文件，用本插件。

## 部署

插件进程要能访问到 DSM 的地址（局域网或公网都可以）。可以跑在 NAS 的 Container Manager 里，也可以跑在同网段的任意机器上。环境变量填平台地址与接入 token（`SOKEL_ENDPOINT` / `SOKEL_TOKEN`）。

## 凭证

| 字段 | 说明 |
|---|---|
| **DSM 地址** | 浏览器里打开 DSM 的地址，带协议和端口，如 `https://nas.example.com:5001`、`http://nas.local:5000` |
| **账号** | DSM 账号 |
| **密码** | 账号密码，加密保存 |
| 跳过证书校验 | 填 `true` 时不校验 HTTPS 证书，**仅用于局域网里 DSM 的自签证书**；走公网请留空 |

账号建议：

- **单独建一个账号**，在「控制面板 → 共享文件夹」里只给它目标文件夹的读写权限。插件只需要上传，不该拿着管理员账号。
- **这个账号不能开两步验证**：接口登录没法输入验证码。DSM 若设置了「强制所有用户启用两步验证」，需要为这个账号单独豁免。
- 账号要有 File Station 的应用权限（「控制面板 → 权限 → File Station」）。

配好后点「检查凭证」：会用账号密码登录一次。失败时提示会指明是地址连不上、证书不受信任、密码不对，还是两步验证的问题。

## 上传文件

| 入参 | 说明 |
|---|---|
| **文件** | 一个或多个平台文件，按原文件名存放 |
| **目标文件夹** | DSM 里看到的路径，**以共享文件夹开头**，如 `/research/入库/2026`。不是 SSH 或容器里的 `/volume1/...` |
| 同名文件 | 报错（默认）/ 覆盖 / 跳过。选「跳过」时，已存在的文件不上传，并在结果里标为已跳过 |
| 自动创建文件夹 | 目标文件夹不存在时逐级创建，默认开 |

出参 `files` 与输入的文件一一对应，每项含文件名、NAS 上的完整路径、大小和是否被跳过；另有上传数和跳过数。

## 注意

- 一次传多个文件时，若中途某个失败，**前面已经传完的会留在 NAS 上**，报错里会写明停在哪个文件、此前传完了几个。重跑时把「同名文件」设为「跳过」，就不会因为已传的文件报错。
- 每个文件会整份读进插件进程再上传，单个文件建议不超过几百 MB。
- 每次调用都登录一次、传完登出，不保留会话。
