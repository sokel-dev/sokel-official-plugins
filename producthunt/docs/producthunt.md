# Product Hunt

读产品、评论和每日榜单；**你的产品下有新评论或新回复时触发工作流**。

**它不能发布产品，也不能回复评论。** Product Hunt 的接口在这两件事上都是只读的。发布当天在网页上操作，
回复评论点事件里的 `url` 去做。插件负责让你第一时间知道有人评论。

## 配置

1. 打开 <https://api.producthunt.com/v2/oauth/applications>，新建一个应用（redirect uri 随便填，如 `https://localhost`）。
2. 应用页下方有 **Developer Token**：它不会过期，代表你自己的账号。
3. 平台里给本插件建一条凭证：

| 字段 | 说明 |
|---|---|
| Developer token | 上一步复制的那串 |
| 出站代理 | 部署环境在国内、连不上 producthunt.com 时必填，如 `http://127.0.0.1:7897` |
| 监听的产品 | slug 或产品页地址，多个用逗号分隔 |
| 监听我做的产品 | 默认 on：token 所属账号作为制作者的最近 10 个产品也一起监听 |
| 轮询间隔（秒） | 默认 180，最短 60 |

点「测试」：会用 token 读一次当前账号。

## 事件：有新评论

监听的产品下有新评论或新回复时触发，同一条只触发一次；你自己写的不触发。

| 字段 | 说明 |
|---|---|
| `comment_id` / `body` | 评论 id 和正文 |
| `url` | 评论地址，**在那里回复** |
| `parent_id` | 回复的是哪条评论；顶层评论为空 |
| `is_reply_to_me` | 回复的是你写的评论 |
| `username` | 评论人。**通常为空**：Product Hunt 对接口隐藏评论人身份（只告诉你是不是你自己），点 `url` 到网页上看是谁 |
| `post_id` / `post_name` / `post_url` | 哪个产品 |
| `votes_count` | 这条评论的得票 |
| `created_at` | 时间 |

第一次启用不会把历史评论推一遍，只从启用那一刻往后算。每个产品每轮按最新顺序翻页，最多 3 页（60 条顶层评论，
每条带最近 5 条回复），一轮之内超过这个量的评论会漏，发布当天评论很密的话把轮询间隔调短一些。

## 操作

| 操作 | 说明 |
|---|---|
| 取产品 | 得票、评论数、上首页时间、制作者 |
| 取评论 | 评论和回复，最新在前；默认 20 条顶层评论，最多 50（Product Hunt 每页 20 条，多的分页取）；`is_mine` 标出你自己写的 |
| 取榜单 | 某一天（按太平洋时间切日）发布的产品，按排名 / 得票 / 最新 |
| 检查凭证 | 读当前账号 |

## 限制

- 不能发布、不能评论、不能投票（接口没有这些写操作）。
- 评论人身份对接口隐藏：评论的 `username` 等字段通常为空，只有「是不是你自己」是准的。
- Product Hunt 按查询复杂度限流，15 分钟一个额度；正常的轮询间隔用不完。
