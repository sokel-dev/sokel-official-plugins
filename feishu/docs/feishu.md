# 飞书（自建应用）

把飞书接进工作流：发消息/卡片、收消息触发、写云文档、读写多维表格。
只想往**一个群**里推通知的话，用更简单的「飞书群机器人」插件即可（不用建应用）。

## 一、创建自建应用（约 5 分钟）

1. 打开[飞书开放平台](https://open.feishu.cn/app)（Lark 国际版：open.larksuite.com）→
   **创建企业自建应用**。
2. 「凭证与基础信息」页复制 **App ID**（cli_ 开头）与 **App Secret** → 粘进本插件凭证。
3. 「应用能力」→ 添加**机器人**。
4. 「权限管理」按需开通（下表），然后**创建版本并发布**——权限改了不发版不生效，
   这是最常见的坑。

| 要用的操作 | 需要的权限 |
|---|---|
| 发消息/回复/撤回 | `im:message`（获取与发送单聊、群组消息） |
| 上传图片/文件 | `im:resource` |
| 查用户（邮箱/手机号→open_id） | `contact:user.employee_id:readonly` 或「通过手机号或邮箱获取用户 ID」 |
| 群列表/建群/拉人 | `im:chat` |
| 云文档 | `docx:document` |
| 多维表格 | `bitable:app` |
| 网盘上传 | `drive:drive` |

5. 发布版本后，让管理员在审批里通过（企业内自建一般秒过）。

## 二、收消息 / 卡片按钮触发工作流（可选）

事件走**长连接**——不需要公网地址，插件自己连向飞书：

1. 开放平台「事件与回调」→ 订阅方式选**使用长连接接收事件**。
2. 「添加事件」勾选：**接收消息 im.message.receive_v1**、
   **机器人进群 im.chat.member.bot.added_v1**（按需）。
3. 用卡片按钮的话：「卡片交互」回调方式同样选长连接。
4. 平台里给凭证配好 app_id/secret 后，事件源自动上线（插件实例页可见状态）。

单聊里用户直接发消息就能触发；**群里要 @机器人** 才收得到（飞书的权限模型，
不是插件筛的）。

## 三、常用操作速查

- **发 Markdown**（推荐）：报告/告警用它，支持 **加粗**、[链接](…)、列表、代码块，
  以卡片渲染，可选标题和标题色。
- **发文本**：`<at user_id="ou_xxx"></at>` @人，`<at user_id="all"></at>` @所有人。
- **查用户**：拿邮箱/手机号换 open_id——**给个人发消息前必经的一跳**。
- **回复消息**：`message_id` 直接绑「收到消息」事件的输出。
- **多维表格**：`app_token` 支持直接粘表格 URL；**先把表格分享给应用**
  （表格右上角 … → 添加文档应用），否则报 1254050。
- **创建云文档**：`folder_token` 建议必填——放应用自己空间里的文档你在网盘看不到。
- **通用调用 call**：以上没覆盖的接口，照飞书文档填 method + path + body 直调，
  token 由插件管。

## 四、排错

| 报错 | 处理 |
|---|---|
| 应用缺权限（99991672） | 开权限后**要重新发布版本** |
| bot 不在这个会话里（230002） | 把机器人拉进群，或核对 chat_id |
| bot 能力未启用（230013） | 「应用能力」添加机器人并发版 |
| 多维表格拒绝访问（1254050） | 把表格分享给应用（添加文档应用） |
| 事件收不到 | 订阅方式必须是「长连接」；事件要勾在**已发布**的版本里 |

## 五、安全

App Secret 只在插件内部换 tenant_access_token，不出现在节点入参、输出、日志里。
一条凭证 = 一个应用；多个应用建多条凭证即可，插件按凭证各起一条事件长连接。
