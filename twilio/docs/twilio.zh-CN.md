# Twilio

发送短信或彩信，查询消息历史与投递状态，并读取账号号码和消息媒体元数据。

## 凭证

将 **账号 SID** 设置为目标 Twilio 账号或子账号标识（`AC` 加 32 位十六进制字符），将 **认证令牌** 设置为该账号的 Auth Token。本版使用 HTTP Basic 认证，固定访问 US1 接口 `https://api.twilio.com/2010-04-01`。不支持 API-key SID、OAuth 令牌、自定义地址或其他 Twilio 区域。账号输出不会包含上游返回的 `auth_token` 字段。

## 操作

| 操作 | 用途 |
| --- | --- |
| `get_account` | 读取账号身份和状态；可显式验证凭证，不会发送消息。 |
| `send_message` | 发送一条短信或彩信，返回消息 SID 和当前状态。 |
| `get_message` | 读取消息、投递状态，以及可用的错误码和价格。 |
| `list_messages` | 读取一页收发消息，可按发送方、接收方或 UTC 发送日期筛选。 |
| `list_incoming_numbers` | 读取一页归属该账号的电话号码。 |
| `get_incoming_number` | 读取账号内的一个电话号码及短信、彩信、语音能力。 |
| `list_message_media` | 读取消息的一页媒体元数据，不下载二进制文件。 |

## 发送与投递

把 `message.to` 设为 E.164 电话号码，例如 `+15558675310`。提供 `message.from` 或 `message.messaging_service_sid`；也可同时提供，从消息服务中选择指定发送方。发送方必须归属于该账号。支持 E.164 号码、短码，以及当地允许的字母数字发送方标识。本操作面向短信和彩信，不支持 WhatsApp 或语音呼叫。

提供非空的 `message.body`（最多 1600 个 Unicode 字符），或一至十个 HTTP/HTTPS `message.media_urls`。这些媒体链接由 Twilio 获取，插件不下载。媒体大小、格式和运营商投递规则由 Twilio 检查。可选的 `smart_encoded=false` 会原样保留，`validity_period` 支持在发送队列中等待 1–36000 秒。一条消息可能拆成多个计费短信段。

发送可能产生费用，需要账号具备合格的发送方和目标地址权限。试用账号及地区注册要求可能限制发送。接受或排队不表示送达：保存返回的 SID，再调用 `get_message` 查询。网络超时也可能发生在 Twilio 已接受发送之后；连接器不会自动重试，也不承诺幂等。手动重试前应先检查消息历史。启动插件和读取账号元数据时均不会发送测试消息。

## 分页与筛选

列表每次读取一页，默认 50 条，最多 1000 条。`has_more` 为真时，将 `next_page_uri` 传入下一次调用的 `page.next_page_uri`，使用同一个操作；查询消息媒体时还应保持消息 SID 相同。继续分页时不要同时提供新筛选条件或分页数量。续页保留上游不透明令牌及查询参数，仅允许指向同一账号和集合。`has_more` 为假时停止。

首次查询消息历史时，可用 `filters.to` 和 `filters.from` 筛选地址。`filters.date_sent` 指定 UTC 日期，或用 `sent_after` / `sent_before` 进行上游的严格日期比较。日期格式为 `YYYY-MM-DD`，不能同时设置精确日期和范围。Twilio 以字符串返回的价格和计数字段保持字符串，避免十进制价格失真。可为空的时间戳、价格和错误字段保持可选。

## 限制与错误

响应最多 8 MiB，表单请求最多 1 MiB。插件拒绝重定向；错误信息不包含认证令牌或上游原始错误正文。HTTP 429 错误包含建议等待时间。插件不购买或删除号码，不修改 Webhook、不发起呼叫、不下载媒体，也不提供消息事件触发器。

## 验证

测试使用 Twilio 发布的 OpenAPI 响应示例，以及明确区分的合成边界场景，核对表单编码、重复媒体字段、分页和认证。本轮开发未验证真实 Twilio 账号或实际短信、彩信投递。准备进行真实验收时，先显式读取账号元数据，再向你控制的接收方发送消息。
