# Miniflux

在自托管 Miniflux 上管理订阅和阅读状态，无需 SaaS 账户。服务器依赖 PostgreSQL，本插件不会安装这两个服务。读取已存储文章可以只在内网完成；订阅和刷新会由 **Miniflux 服务器**抓取订阅源及已配置的正文抓取资源，因此公开订阅源仍需要外网。本插件不会开启第三方集成，不自行抓取文章网址，也不会执行已存储的 HTML。

## 配置连接

将部署环境变量 `SOKEL_MINIFLUX_URL` 设置为实例根地址，例如 `http://miniflux:8080` 或 `https://reader.example.org/rss`。支持内网 HTTP 和反向代理路径前缀。不要追加 `/v1`，不要在地址中放入凭证、查询参数或片段。没有默认公共服务地址。容器中的 `localhost` 指插件容器自身。

在自己的 Miniflux 中进入 **Settings → API Keys** 创建 API key，保存到插件的 **API 密钥**凭证字段。请求通过 `X-Auth-Token` 发送密钥；服务地址不放在凭证中。密钥以对应用户的身份工作。可用 **获取当前用户**进行只读凭证检查，它只返回用户 ID 和用户名。

本接口面向 Miniflux **2.3.2 及以上**，因为显式设置 `starred` 从 2.3.2 才开始支持。全部九个操作已在隔离的 **2.3.5** 实例及合成本地 RSS 上验收；这不代表对所有版本的完整兼容保证。Miniflux 采用 Apache-2.0 许可。

## 操作

| 操作 | 输入与行为 |
| --- | --- |
| 获取当前用户 | 读取 API 密钥对应的身份，不返回账户设置或密码。 |
| 列出分类 | 返回当前用户的分类 ID 和标题。 |
| 创建分类 | 创建分类，标题不能为空，最多 1024 个 UTF-8 字节。 |
| 列出订阅 | 返回筛选后的订阅信息：ID、标题、订阅源与站点网址、分类、检查时间、禁用状态及解析错误次数；不返回保存的订阅认证信息和 Cookie。 |
| 订阅订阅源 | 提供 HTTP(S) 订阅源网址及已有分类 ID，返回新订阅 ID。服务器会抓取订阅源；本接口不配置需认证的订阅源。 |
| 请求刷新订阅 | 刷新一个已有订阅。单订阅刷新 API 是同步请求，返回 HTTP 204；`accepted=true` 只确认该响应，不保证有新文章或没有解析错误。之后可通过列出订阅检查。 |
| 列出已存文章 | 按下面的过滤条件读取一页已存文章，不抓取文章原站。 |
| 获取已存文章 | 按 ID 读取一篇文章，包括已存 HTML 正文和阅读状态。 |
| 更新阅读状态 | 更新 1–1000 个不重复的文章 ID。在 `changes` 中提供 `status`、`starred` 或两者。显式传 `false` 会取消收藏。 |

ID 使用**正十进制字符串**，不要传工作流数字，以保留超过 JavaScript 精确整数范围的值。ID 必须在有符号 64 位整数范围内。分类与订阅列表在 8 MiB 响应上限内返回服务器的完整数组，不会偷偷分页或截断。

## 文章过滤与续读

`options` 可以包含 `limit`（1–1000，默认 100）、`after_id`、`category_id`、`status`、`starred` 和 `search`（最多 4096 个 UTF-8 字节）。状态为 `read`、`unread` 或 `removed`。`starred=true` 只选收藏文章，`false` 只选未收藏文章，不填写则不按收藏状态过滤。文章始终按 ID 升序排列；`after_id` 为不包含自身的游标。

每次返回非空页后，保存 `next_after_id`，下次作为 `after_id` 传入，其他过滤条件保持一致。`may_have_more=true` 表示当前页已满，最后仍可能遇到一个空页；它不代表精确剩余数量。处理未读文章时，以 ID 续读可避免将前一页标为已读后，偏移量分页跳过文章的问题。并发变化不会形成固定快照，周期轮询时应自行保存检查点。本版本没有事件触发器。

第一页示例：

```json
{"options":{"limit":100,"status":"unread","category_id":"2"}}
```

更新示例：

```json
{"entry_ids":["101","102"],"changes":{"status":"read","starred":false}}
```

`removed` 修改存储的阅读状态；本插件不提供分类或订阅删除。返回正文是来自订阅源的不可信 HTML，下游应按数据处理。

## 失败行为与限制

HTTP 客户端超时为 60 秒，请求体上限 1 MiB，响应体上限 8 MiB。禁用重定向和自动写入重试；错误不包含上游原始响应体或认证秘密。写入超时后应先检查服务器当前状态，再决定是否重试；超时不代表写入失败。服务器网络策略和源站限制都可能导致订阅抓取失败。

本插件不提供服务器或用户管理、OPML 导入导出、第三方稍后读推送、订阅认证信息、抓取规则、附件和原文抓取。源码及本地测试不代表镜像或市场版本已经发布。
